## 二、產品背景

請你們開發一個 **Prompt / Skill 收藏庫**。

使用者可以登入會員，在前台瀏覽 Prompt / Skill 資料，並收藏自己常用的項目。管理者可以登入後台，新增類別、管理 Prompt / Skill 資料，讓整個收藏庫可以持續整理與擴充。

這個專案的重點不是做出大型知識平台，而是練習：

- 如何設計會員與管理者兩種角色
- 如何做登入、權限檢查與後台管理
- 如何設計類別、資料、收藏之間的關係
- 如何做前台列表、搜尋、篩選與收藏
- 如何把 AI 常用素材整理成未來真的會用的工具

---

## 三、產品目標

這個專案要完成一個可以 Demo 的 AI 素材收藏服務：

- 管理者可以登入後台
- 管理者可以新增 / 編輯 / 刪除類別
- 管理者可以新增 / 編輯 / 刪除 Prompt / Skill 資料
- 會員可以登入前台
- 會員可以瀏覽、搜尋、篩選 Prompt / Skill
- 會員可以收藏常用的 Prompt / Skill
- 系統能區分會員與管理者權限
- 小組能說清楚使用哪些 AI 服務加速開發，以及自己做了哪些判斷

## 五、非目標

這些事情不是 MVP 階段的重點。除非主流程已經穩定，否則不要一開始就做。

- 不需要做第三方 OAuth 登入，例如 Google / GitHub 登入
- 不需要做忘記密碼、Email 驗證、簡訊驗證
- 不需要做付款、訂閱或權限方案
- 不需要做多人團隊協作空間
- 不需要做公開投稿審核流程
- 不需要做很完整的富文字編輯器
- 不需要做大型搜尋引擎或全文檢索
- 不需要一開始就部署到正式環境

## 六、角色與權限

| 角色 | 可以做什麼 | 不能做什麼 |
|---|---|---|
| 未登入訪客 | 可以看首頁或登入頁 | 不能收藏，不能進後台 |
| 會員 | 可以登入、瀏覽資料、搜尋、篩選、收藏 / 取消收藏 | 不能新增類別，不能新增 / 編輯 / 刪除 Prompt / Skill |
| 管理者 | 可以登入後台、管理類別、管理 Prompt / Skill 資料 | 不應該直接看到其他會員密碼或敏感資料 |

MVP 至少需要準備：

- 1 個管理者測試帳號
- 1 個會員測試帳號

## 七、目標使用者與情境

你們可以想像使用者是：

- 常常使用 AI 的學生
- 想整理工作 Prompt 的行銷 / 行政 / 開發者
- 想把常用 Claude Code / ChatGPT 指令收藏起來的人
- 想建立自己 Skill 素材庫的 AI 工具使用者

核心任務：

> 我常常有很多 Prompt / Skill，不想每次都重新找。我希望有一個地方可以分類、搜尋、收藏，讓我下次更快拿來用。

| 5 | 資料管理 | 管理者可以新增 Prompt / Skill 資料 |

## 十二、建議 API

你們可以依照自己的設計調整，但 MVP 至少要支援下列類型。

### Auth

| Method | Path | 權限 | 說明 |
|---|---|---|---|
| `GET` | `/health` | 公開 | 確認服務正常 |
| `POST` | `/auth/login` | 公開 | 會員 / 管理者登入 |
| `POST` | `/auth/logout` | 已登入 | 登出 |
| `GET` | `/auth/me` | 已登入 | 取得目前登入者資訊 |

### 前台資料

| Method | Path | 權限 | 說明 |
|---|---|---|---|
| `GET` | `/categories` | 已登入 | 取得類別列表 |
| `GET` | `/skills` | 已登入 | 取得 Prompt / Skill 列表，支援 `keyword`、`categoryId` |
| `GET` | `/skills/:id` | 已登入 | 取得單筆詳情 |
| `POST` | `/favorites/:skillId` | 會員 | 收藏 |
| `DELETE` | `/favorites/:skillId` | 會員 | 取消收藏 |
| `GET` | `/me/favorites` | 會員 | 我的收藏 |

### 後台管理

| Method | Path | 權限 | 說明 |
|---|---|---|---|
| `POST` | `/admin/categories` | 管理者 | 新增類別 |
| `PATCH` | `/admin/categories/:id` | 管理者 | 編輯類別 |
| `DELETE` | `/admin/categories/:id` | 管理者 | 刪除類別 |
| `POST` | `/admin/skills` | 管理者 | 新增 Prompt / Skill |
| `PATCH` | `/admin/skills/:id` | 管理者 | 編輯 Prompt / Skill |
| `DELETE` | `/admin/skills/:id` | 管理者 | 刪除 Prompt / Skill |

## 十三、資料規格

MVP 需要資料持久化。可以先用 JSON 檔案實作，進階組可以改用 PostgreSQL / TypeORM。請不要只存在瀏覽器 `localStorage`，否則後端就沒有真的管理資料。

### User

| 欄位 | 說明 |
|---|---|
| `id` | 使用者 ID |
| `name` | 顯示名稱 |
| `email` | 登入信箱或帳號 |
| `passwordHash` | 密碼雜湊，不要存明碼 |
| `role` | `member` 或 `admin` |

### Category

| 欄位 | 說明 |
|---|---|
| `id` | 類別 ID |
| `name` | 類別名稱 |
| `description` | 類別說明 |

### SkillItem

| 欄位 | 說明 |
|---|---|
| `id` | Prompt / Skill ID |
| `title` | 標題 |
| `categoryId` | 所屬類別 ID |
| `tags` | 標籤陣列 |
| `content` | Prompt / Skill 內容 |
| `useCase` | 適用情境 |
| `exampleInput` | 範例輸入，可選 |
| `createdAt` | 建立時間 |
| `updatedAt` | 更新時間 |

### Favorite

| 欄位 | 說明 |
|---|---|
| `userId` | 會員 ID |
| `skillId` | Prompt / Skill ID |
| `createdAt` | 收藏時間 |

## 十四、錯誤處理需求

| 情境 | 建議狀態碼 | 回應訊息 |
|---|---:|---|
| 登入失敗 | 401 | 帳號或密碼錯誤 |
| 未登入 | 401 | 請先登入 |
| 權限不足 | 403 | 你沒有權限執行此操作 |
| 類別名稱空白 | 400 | 請輸入類別名稱 |
| Prompt / Skill 標題空白 | 400 | 請輸入標題 |
| Prompt / Skill 內容空白 | 400 | 請輸入內容 |
| 找不到資料 | 404 | 找不到指定資料 |
| 重複收藏 | 409 | 已經收藏過此項目 |
| 系統錯誤 | 500 | 系統發生錯誤，請稍後再試 |

## 十五、邊界情境

| 情境 | 建議處理 |
|---|---|
| 會員直接打開後台網址 | 導回前台或顯示權限不足 |
| 未登入直接收藏 | 要求先登入 |
| 管理者刪除已有資料的類別 | 阻擋刪除或提醒先移動資料 |
| 搜尋沒有結果 | 顯示空狀態，不要當成錯誤 |
| 收藏清單是空的 | 顯示「尚未收藏」提示 |
| 同一會員重複收藏同一筆資料 | 不要產生重複資料 |
| 密碼錯誤 | 不要透露帳號是否存在，只提示帳號或密碼錯誤 |

## 十六、技術限制

| 限制 | 說明 |
|---|---|
| 必須有前台 | 會員要能瀏覽、搜尋、收藏 |
| 必須有後台 | 管理者要能登入後管理類別與資料 |
| 必須有權限檢查 | 不能只靠前端隱藏按鈕，後端 API 也要檢查 |
| 密碼不可明碼儲存 | 建議使用 `bcrypt` |
| MVP 可以用 JSON 檔案 | 但資料必須可持久化，不要只放記憶體或 localStorage |
| 不要求部署 | 本機能跑、能 Demo 即可；部署是加分 |

## 十九、產品用心點

這次成果發表不只看功能有沒有跑，也會看你們在產品上用了哪些心。

可以從這些方向挑一到兩個做：

- 類別命名清楚，讓人知道怎麼找資料
- Prompt / Skill 詳情頁有適用情境與使用方式
- 搜尋沒有結果時有友善空狀態
- 收藏按鈕狀態清楚，知道已收藏或未收藏
- 後台表單有清楚錯誤提示
- README 提供測試帳號與操作流程
- 提供範例資料，讓第一次打開的人有東西可以測
- 增加一鍵複製 Prompt 內容

## 二十一、風險與取捨

| 風險 | 可能狀況 | 建議取捨 |
|---|---|---|
| 登入權限卡太久 | JWT / session 不熟，導致其他功能做不出來 | 先做最小登入與角色檢查，不要做 OAuth |
| 後台做太大 | 類別、資料、會員都想完整 CRUD | MVP 先做類別新增與 Prompt / Skill 新增 |
| 搜尋做太複雜 | 想做全文檢索、排序、推薦 | MVP 先做簡單 keyword includes |
| 資料庫卡住 | DB schema 或 ORM 設定不熟 | 先用 JSON 檔案完成主流程，DB 當加分 |
| 權限只做前端 | 前端藏按鈕但 API 沒擋 | 後端 API 必須檢查角色 |
| 分工不均 | 一人做全部，其他人只做文案 | 每人至少負責一個可展示成果 |

## 二十四、AI 協作紀錄

請在 README 或成果發表中補一小段「AI 協作紀錄」。不用寫很長，但要具體。

可以包含：

- 使用了哪些 AI 服務，例如 ChatGPT、Claude、Copilot、Gemini、Cursor、v0、Figma AI 等
- AI 幫忙做了哪些事，例如拆資料模型、設計 API、檢查權限流程、產生前台表單、寫 README
- 哪些地方不能直接照 AI，需要小組自己判斷，例如權限設計、MVP 範圍、資料是否真的可存取、程式碼是否真的可跑
- 一個最有幫助的 AI prompt 或對話片段摘要

範例：

```md
### AI 協作紀錄

- 使用工具：ChatGPT、GitHub Copilot
- 加速的地方：協助設計 users / categories / skills / favorites 資料結構，整理後台 API
- 小組自己的判斷：最後決定 MVP 只做會員收藏，不做公開投稿，避免權限流程太複雜
- 最有幫助的 prompt：請 AI 幫我們檢查「會員和管理者權限可能有哪些漏洞」
```
